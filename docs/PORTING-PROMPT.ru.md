# Промпт для агента: перенос DLSSNR-AMD 0.0.8.3 на RDNA3

Выполни перенос изменений DLSSNR-AMD версии 0.0.8.3 в этот форк для Linux/Proton и AMD RDNA3.
Нужна реализация с воспроизводимой сборкой, проверками и артефактом для испытания на целевой карте.

## Что перенести

Составь до изменения поведения матрицу изменений 0.0.8.1–0.0.8.3, приёмки и проверки каждого пункта.
Затем реализуй перенос по этапам с отдельными понятными коммитами:

1. Общие изменения UI/NR Control, hotkeys, локализации, Unicode-путей, исправления frame generation,
   смены и динамического разрешения, History Precision, Memory Guard, выделения и переиспользования VRAM.
   Сначала добейся сборки с базовыми CC_SMALL_FP8 и CC_SILVER_AARDWOLD на существующем RDNA3 backend.
2. Адаптируй новые сетевые режимы: CC_SMALL_FP8_EXPERIMENTAL и CC_SILVER_AARDWOLD_OPTIMIZED,
   включая уровни Quality/Balanced/Performance/Ultra Performance. Обнови установку и миграцию моделей,
   конфигурацию, manifest, шейдеры и соответствующие проверки.
3. Собери Linux x86_64 RDNA3-пакет, проверь отсутствие моделей/проприетарных DLL внутри и подготовь
   инструкции запуска и испытания на целевой машине.

Неполный перенос общих исправлений — промежуточный результат. Для каждого отсутствующего режима
укажи конкретную техническую причину и оставшуюся работу; не представляй его реализованным.
Существующий функционал RDNA3 и режимы RDNA4 сохраняй. Изменения Windows делай только при необходимости.

## Уже найденные места, требующие внимания

Предварительное git merge-tree объединение исходного rdna3 с v0.0.8.3 дало 10 конфликтных файлов
и 15 блоков конфликтов; с v0.0.8.1 — 5 файлов, с v0.0.8.2 — 7. Это проверка слияния, не готовый перенос.

- Скрипты linux/build/{assemble_product_data.sh,build_int4.sh,build_network.py,build_package.sh}.
- linux/package/make_ini.py, src/core/{nr_shader_manifest.hpp,nrvk.hpp},
  src/pe/{nr_pe_config.cpp,nr_pe_config.hpp,nr_pe_session.cpp}.
- В nr_graph.cpp и nr_runtime.cpp часть правок сливается автоматически, но требует смысловой проверки.
- RDNA3 хранит e4m3 как FP16 в отдельных twin-буферах. Новое descriptor retargeting и повторное
  использование памяти обязаны учитывать эти буферы и raw alias bindings.
- Экономия VRAM зависит также от шейдеров и manifest: RDNA3 пока не содержит новые ключи
  post_no_out1 и noise_buffer. Нельзя обещать выигрыш RX 9070 XT после одного переноса C++.
- 0.0.8.3 заменяет старый CC_SILVER_AARDWOLD_INT4_MIXED новой optimized-моделью и меняет таблицы.
  Старые RDNA3 INT4 kernels нельзя без проверки оставить с новыми таблицами.
- У RDNA3 нет pipelines-experimental.json, pipelines-optimized.json, pipelines-performance.json
  и pipelines-ultra.json. Одного копирования JSON недостаточно: реализуй используемые ими вычисления.
- В arch/rdna3.sh имя модели ещё dlssnr.bin, upstream installer использует CC_SILVER_AARDWOLD.bin.
- Сохрани собственный temporal reuse форка и согласуй его с исправлениями frame generation.
- Upstream содержит экспериментальную RDNA3-поддержку Windows на основе этого форка; используй
  её как справочный материал, а не как готовую замену Linux/Proton backend.

## Проверки и доставка

Пользуйся закреплёнными зависимостями fetch_deps.sh, не подменяй glslang случайной системной версией.
Проверь компиляцию всех добавленных shader variants, host и пакета. Используй существующие
check_rdna3.py, check_rdna3_small.py и check_rdna3_int4.py там, где они проверяют ту же сеть.
Неизменённая математика должна оставаться EXACT. Для намеренно изменённых сетей/точности опиши
референс, критерии качества и обоснованные новые эталоны. Не ослабляй проверки ради зелёного результата.

На homeserver нет целевой GPU RDNA3. Выполни доступные CPU/static/build/package проверки.
GPU-зависимые сценарии перечисли как непроверенные и подготовь команды, входные данные и перечень
логов для Игоря: базовые модели, все новые режимы, смена модели и разрешения, frame generation,
меню во время смены разрешения, длительная работа, VRAM и время кадра. Проверка сборки не заменяет
игровую проверку. Не устанавливай GPU-драйверы или сервисы и не используй соседние машины без задачи.

Не коммить и не распространяй NVIDIA DLL, веса и пакеты с ними. Сохрани лицензии и атрибуцию.
Закоммить результат и отправь рабочую ветку в origin. Не создавай upstream PR и release tag автоматически.
Оставь в проекте отчёт о функциях, фактически выполненных проверках, расположении пакета,
порядке установки/отката и точных оставшихся ограничениях. Если целевая проверка недоступна,
передай пригодную для неё сборку с этим статусом, не объявляй GPU-корректность доказанной.
